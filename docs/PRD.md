# PRD.md — Product Requirements Document
**Project:** TenderSentry  
**Version:** 1.0 MVP  
**Hackathon Theme:** HUMAN + AI: BETTER TOGETHER  
**Date:** 2026-10-17  

---

## 1. Problem Statement

Public procurement tenders in Pakistan (and globally) are routinely distributed as multi-document PDF packages — a main notice, schedules, bills of quantities, technical specifications, and addenda. These documents are written by different teams at different times. The result is contradictions: a deadline stated on one page that conflicts with another, a requirement that appears mandatory in one schedule and optional in another, financial figures that don't add up.

Procurement officers, bidders, and auditors currently catch these contradictions **manually** — or not at all. Missed contradictions cost money, trigger disputes, and enable corruption.

---

## 2. Goals & Non-Goals

### Goals (MVP)
- Automatically detect cross-document contradictions in tender PDFs.
- Explain each finding in plain language a procurement officer can act on.
- Present findings to a human reviewer with one-click Flag / Dismiss / Escalate decisions.
- Log every human decision with a timestamp for audit purposes.
- Demonstrate a credible Human + AI pipeline to hackathon judges.

### Non-Goals (explicitly out of scope for MVP)
- Multi-user authentication / role-based access.
- Email or notification delivery.
- Export to PDF / Excel.
- Real-time multi-session support.
- Uploading real government tenders from the internet.
- Mobile app.

---

## 3. Target Users

| Persona | Role | Pain |
|---|---|---|
| Procurement Officer | Reviews incoming bids | Manually cross-checks 50+ pages per tender |
| Bid Evaluator / Auditor | Validates award decisions | Needs evidence of inconsistencies |
| Anti-Corruption Investigator | Detects manipulation | Needs a traceable, explainable contradiction log |

For the MVP demo, the user is a **procurement officer** reviewing a three-document tender package.

---

## 4. Functional Requirements

| ID | Feature | Priority |
|---|---|---|
| FR-001 | Upload 2–5 tender PDF documents via the web UI | Must Have |
| FR-002 | Extract full text from each PDF page | Must Have |
| FR-003 | Detect contradictions deterministically (dates, amounts, requirement keywords) | Must Have |
| FR-004 | Generate plain-language explanation for each contradiction via LLM (GPT-OSS-120B) | Must Have |
| FR-005 | Validate each finding with TypeSafe AI jev (genuine probability + severity score) | Must Have |
| FR-006 | Present findings one at a time to a human reviewer with Flag / Dismiss / Escalate buttons | Must Have |
| FR-007 | Log every human decision to SQLite with timestamp | Must Have |
| FR-008 | Display a final summary dashboard: total found, flagged, dismissed, escalated | Must Have |
| FR-009 | Show audit log table of all decisions in the UI | Should Have |
| FR-010 | Rotate across three Groq API keys automatically on rate limit | Must Have |

---

## 5. Non-Functional Requirements

| ID | Requirement |
|---|---|
| NFR-001 | End-to-end analysis of 3 PDFs must complete in under 60 seconds |
| NFR-002 | LLM output must conform to Pydantic schema (enforced by instructor library) |
| NFR-003 | jev validation must fail gracefully — if API is unavailable, fall back to LLM-only confidence |
| NFR-004 | All API keys stored in `.env`; never committed to git |
| NFR-005 | SQLite audit log is append-only; no decision may be deleted via the UI |
| NFR-006 | System must run locally with `uvicorn main:app` on Python 3.11+ |

---

## 6. MVP Scope Summary

**In scope:**
- 3 synthetic PDFs generated by `generate_docs.py` (main notice, schedule A, bill of quantities)
- 3 planted contradictions: deadline mismatch, certification wording, math error
- LangGraph agent with 4 nodes: extract → compare → investigate → hitl_review
- FastAPI backend + vanilla HTML/CSS/JS frontend (single page)
- SQLite audit log

**Out of scope:** see Non-Goals above.

---

## 7. Success Criteria (Hackathon Demo)

- A judge uploads the 3 PDFs, clicks "Analyse", and sees all 3 contradictions surfaced within 60 seconds.
- Each finding shows the conflicting excerpts side-by-side with a plain-language explanation.
- The judge clicks Flag / Escalate / Dismiss and sees the audit log update instantly.
- The pipeline story — deterministic detection → LLM explanation → jev validation → human decision — is explainable in 2 minutes.

## 8. Assumptions & Risks

| Assumption | Risk |
|---|---|
| Groq API keys are valid and have quota | Medium — mitigated by key rotation + emergency fallback model |
| TYPESAFE_API_KEY works at demo time | Medium — jev failure is handled gracefully; system still works |
| PyMuPDF correctly parses reportlab-generated PDFs | Low — both are standard PDF |
| No live internet is needed during demo | Low — all models are cloud API, no local GPU needed |
